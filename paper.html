AbstractAbstrak

This article presents Myszkowski Byte Cipher, a browser-based implementation that extends the classical Myszkowski transposition to arbitrary byte sequences. The method adds an optional rolling-key schedule that rotates the key once per block, and an optional reversible low-hex-nibble transform applied after transposition. Output is stored in a versioned 16-byte .mysz container carrying the mode, row count, original length and a CRC32 checksum. Because the implementation operates on raw bytes, it can process text, images, PDF and Office files without interpreting their format. All processing is local; no data is sent to a server. An interactive laboratory reproduces the timing and repeated-block measurements described below. The work is intended for education and reproducible experimentation and is not an authenticated encryption scheme.

Artikel ini memaparkan Myszkowski Byte Cipher, implementasi berbasis browser yang memperluas transposisi Myszkowski klasik ke deret byte sembarang. Metode ini menambahkan jadwal kunci berputar (rolling key) opsional yang memutar kunci pada setiap blok, serta transformasi low-hex-nibble opsional yang dapat dibalik setelah transposisi. Keluaran disimpan dalam kontainer .mysz berversi sepanjang 16 byte yang memuat mode, jumlah baris, panjang asli, dan checksum CRC32. Karena bekerja pada byte mentah, implementasi ini dapat memproses teks, gambar, PDF, dan file Office tanpa menafsirkan formatnya. Seluruh pemrosesan berlangsung lokal; tidak ada data dikirim ke server. Laboratorium interaktif mereproduksi pengukuran waktu dan uji blok berulang yang dijelaskan di bawah. Karya ini ditujukan untuk pendidikan dan eksperimen yang dapat direproduksi, dan bukan skema enkripsi terotentikasi.

1IntroductionPendahuluan

Classical transposition ciphers rearrange symbols without altering their values. They remain valuable teaching tools for permutation, repeated-key handling, block processing, and the distinction between reversible obfuscation and cryptographic confidentiality. The Myszkowski variant differs from simple columnar transposition by assigning equal ranks to repeated key characters and reading those columns together, row by row.

Cipher transposisi klasik menyusun ulang simbol tanpa mengubah nilainya. Cipher ini tetap berguna sebagai bahan ajar tentang permutasi, penanganan kunci berulang, pemrosesan blok, serta perbedaan antara pengaburan yang dapat dibalik dan kerahasiaan kriptografis. Varian Myszkowski berbeda dari transposisi kolom sederhana karena memberi peringkat sama pada karakter kunci yang berulang dan membaca kolom-kolom tersebut bersama, baris demi baris.

This project investigates three practical research questions:

Proyek ini menelaah tiga pertanyaan penelitian praktis:

  1. RQ1. Can Myszkowski transposition be applied safely to arbitrary bytes rather than only alphabetic text?RQ1. Dapatkah transposisi Myszkowski diterapkan dengan aman pada byte sembarang, bukan hanya teks alfabet?
  2. RQ2. Does rotating the key between blocks reduce identical ciphertext blocks in a repeated-data experiment?RQ2. Apakah memutar kunci antarblok mengurangi blok ciphertext yang identik pada eksperimen data berulang?
  3. RQ3. What is the effect of a reversible low-nibble offset applied after transposition?RQ3. Apa pengaruh offset low-nibble yang dapat dibalik setelah transposisi?

The classical transposition basis is taken from the publication cited in [1]. The rolling-key schedule, byte-oriented processing, nibble options, .mysz container, browser interface and validation strategy are extensions made in this project and are not attributed to that publication.

Dasar transposisi klasik diambil dari publikasi yang dirujuk pada [1]. Jadwal kunci berputar, pemrosesan berbasis byte, opsi nibble, kontainer .mysz, antarmuka browser, dan strategi validasi merupakan perluasan dalam proyek ini dan tidak dinisbatkan kepada publikasi tersebut.

2.2Block layout and read orderTata letak blok dan urutan baca

For key length c and row count r, the block size is B = c × r bytes. The input is divided into blocks of B bytes; only the final block is zero-padded, and the original length stored in the header is used to remove padding. For each rank in ascending order, a unique column is read top-to-bottom, whereas columns sharing a rank are read left-to-right within each row. The resulting permutation is applied to every block independently.

Untuk panjang kunci c dan jumlah baris r, ukuran blok adalah B = c × r byte. Masukan dibagi menjadi blok B byte; hanya blok terakhir yang diberi padding nol, dan panjang asli pada header digunakan untuk membuang padding. Untuk setiap peringkat menaik, kolom unik dibaca atas ke bawah, sedangkan kolom yang berbagi peringkat dibaca kiri ke kanan pada tiap baris. Permutasi yang dihasilkan diterapkan pada setiap blok secara independen.

2.3Rolling-key scheduleJadwal kunci berputar

In static mode every block uses the original key. In rolling mode, block b uses the key rotated left by b mod c. The schedule therefore repeats after c blocks; it alters block arrangement but does not provide the unpredictability of a cryptographic keystream.

Pada mode statis setiap blok memakai kunci asli. Pada mode berputar, blok b memakai kunci yang diputar ke kiri sebanyak b mod c. Jadwal ini berulang setiap c blok; ia mengubah susunan blok tetapi tidak memberi ketidakterdugaan seperti aliran kunci kriptografis.

2.4Low-hex-nibble transformTransformasi low-hex-nibble

When enabled, the transform is applied after transposition to every byte, with offset k ∈ {9, 7}:

Jika diaktifkan, transformasi diterapkan setelah transposisi pada setiap byte, dengan offset k ∈ {9, 7}:

output = (byte & 0xF0) | (((byte & 0x0F) + k) mod 16)

Decryption applies the additive inverse modulo 16. The offset is recorded in the header, so it is a transform parameter and not secret key material.

Dekripsi memakai invers aditif modulo 16. Offset dicatat di header, sehingga ia adalah parameter transformasi, bukan materi kunci rahasia.

3ImplementationImplementasi

The system is framework-free and consists of static HTML, CSS and JavaScript modules. A versioned 16-byte header precedes the transformed payload; all multi-byte integers are big-endian.

Sistem ini tanpa framework dan terdiri dari modul HTML, CSS, dan JavaScript statis. Header berversi 16 byte mendahului payload yang ditransformasi; semua bilangan multibyte memakai big-endian.

Before transformation, decryption validates the magic marker, version, flags, key, row count, payload length against block size, and original length against padding. After reversal, the CRC32 of the recovered data is compared with the header value. An automated suite of 12 regression tests covers key ordering, known vectors, round trips, wrong keys, invalid files, nibble offsets, strict hex input and repeated-block behaviour.

Sebelum transformasi, dekripsi memvalidasi penanda magic, versi, flag, kunci, jumlah baris, panjang payload terhadap ukuran blok, dan panjang asli terhadap padding. Setelah pembalikan, CRC32 data hasil pemulihan dibandingkan dengan nilai header. Rangkaian 12 uji regresi otomatis mencakup urutan kunci, vektor uji, round trip, kunci salah, file tidak valid, offset nibble, masukan hex ketat, dan perilaku blok berulang.

4ExperimentsEksperimen

The cipher is available as a standalone browser application that implements every step described above. Configure the key, row count, schedule and nibble offset, then encrypt text or files and run the timing and repeated-block measurements. To reproduce results for a paper, record the browser, operating system, hardware, key, row count, schedule, nibble offset, input size and the raw CSV output.

Cipher ini tersedia sebagai aplikasi browser mandiri yang menerapkan setiap langkah di atas. Atur kunci, jumlah baris, jadwal, dan offset nibble, lalu enkripsi teks atau file dan jalankan pengukuran waktu serta uji blok berulang. Untuk mereproduksi hasil pada makalah, catat browser, sistem operasi, perangkat keras, kunci, jumlah baris, jadwal, offset nibble, ukuran masukan, dan keluaran CSV mentah.

4.1Measurement protocolProtokol pengukuran

Timing benchmark. Input sizes of 10 KiB, 100 KiB, 512 KiB, 1 MiB and 5 MiB are filled with cryptographically random bytes. Each size is encrypted and decrypted five times; the mean and population standard deviation are reported in milliseconds.

Benchmark waktu. Ukuran masukan 10 KiB, 100 KiB, 512 KiB, 1 MiB, dan 5 MiB diisi byte acak kriptografis. Tiap ukuran dienkripsi dan didekripsi lima kali; rerata dan simpangan baku populasi dilaporkan dalam milidetik.

Repeated-block test. One random block is repeated 300 times and the number of distinct ciphertext blocks is counted. Static mode yields a single distinct block; rolling mode yields at most as many as the key length. This is evidence of changed block arrangement, not of semantic security.

Uji blok berulang. Satu blok acak diulang 300 kali dan jumlah blok ciphertext yang berbeda dihitung. Mode statis menghasilkan satu blok berbeda; mode berputar paling banyak sebanyak panjang kunci. Ini bukti perubahan susunan blok, bukan keamanan semantik.

5Security analysis and limitationsAnalisis keamanan dan keterbatasan

Transposition preserves byte frequencies and file structure, so the scheme is vulnerable to frequency, structural, known-plaintext and chosen-plaintext analysis. The nibble transform is deterministic, reversible and independent of any secret, and therefore does not change this assessment. Claims are limited to reversible transformation, integrity-error detection and measured experimental behaviour.

Transposisi mempertahankan frekuensi byte dan struktur file, sehingga skema ini rentan terhadap analisis frekuensi, struktural, known-plaintext, dan chosen-plaintext. Transformasi nibble bersifat deterministik, dapat dibalik, dan tidak bergantung pada rahasia apa pun, sehingga tidak mengubah penilaian ini. Klaim dibatasi pada transformasi yang dapat dibalik, deteksi kesalahan integritas, dan perilaku eksperimen yang terukur.

For real confidentiality, the transformation should be replaced by a standard AEAD construction with keys derived through a password-based KDF such as Argon2id or scrypt.

Untuk kerahasiaan yang sesungguhnya, transformasi harus diganti dengan konstruksi AEAD standar dengan kunci yang diturunkan melalui KDF berbasis kata sandi seperti Argon2id atau scrypt.

6Conclusion and future workKesimpulan dan pekerjaan lanjutan

Myszkowski Byte Cipher shows that Myszkowski transposition can be applied to arbitrary bytes with strict validation, and provides a transparent platform for observing how a rolling key changes block arrangement. It is a pedagogical artefact rather than a secure cipher. Planned work includes a clearly labelled authenticated-encryption mode, Web Crypto key derivation as a secure baseline, property-based tests for arbitrary block sizes and Unicode keys, a downloadable experiment manifest with environment metadata, automated accessibility checks, and a comparison of static, rolling, nibble-7 and nibble-9 variants against a baseline.

Myszkowski Byte Cipher menunjukkan bahwa transposisi Myszkowski dapat diterapkan pada byte sembarang dengan validasi ketat, serta menyediakan platform transparan untuk mengamati bagaimana kunci berputar mengubah susunan blok. Karya ini adalah artefak pedagogis, bukan cipher yang aman. Pekerjaan lanjutan mencakup mode enkripsi terotentikasi yang berlabel jelas, penurunan kunci dengan Web Crypto sebagai pembanding aman, uji berbasis properti untuk ukuran blok sembarang dan kunci Unicode, manifes eksperimen yang dapat diunduh beserta metadata lingkungan, pemeriksaan aksesibilitas otomatis, dan perbandingan varian statis, berputar, nibble-7, dan nibble-9 terhadap pembanding.
